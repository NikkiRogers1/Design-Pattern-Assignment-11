Phase 2- 
In this phase I created a VirtualMediaProxy, implemented the MediaItem interface, stored the title and duration, and used a null check to delay creating RealMedia. The lazy loading works by checking whether realMedia is null. If it is, the program prints the loading message and creates the object. If it isn't null, it does nothing and reuses the existing object. Waiting until someone actually requests the media before creating the object helps prevent loading it into memory before it is needed. The difference between the Remote Proxy and Virtual Proxy is that the Remote Proxy waits until a method is called to establish a connection to the remote object, while the Virtual Proxy waits until a method is called to create the actual object. Both implement the same MediaItem interface, which allows Main to use either proxy through the same methods even though they behave differently. I didn't have any major problems implementing lazy loading. I understood how the null check worked and why I needed to call loadIfNeeded() in all three methods. When I tested the program, the loading message only printed once, and the remaining method calls reused the existing object.
